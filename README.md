# Поля

Инструмент совместного чтения: спрятанные в тексте задания, пасхалки и экран результатов для преподавателя. Готовы этапы 0–3: каркас и вход, загрузка PDF и разбивка на абзацы, читалка с учётом дочитывания, спрятанные задания.

## Что уже работает

- Вход по одноразовой ссылке на почту, без пароля. Ссылка действует 15 минут и подтверждается кнопкой, чтобы почтовые сканеры её не сжигали.
- Создавать курсы могут адреса из `TEACHER_EMAILS`.
- У курса есть ссылка-приглашение для студентов. Её можно заменить, старая перестаёт работать.
- Преподаватель видит список участников курса.
- Преподаватель загружает PDF, сервис делит его на абзацы, заголовки и исключённые фрагменты (колонтитулы, номера страниц, сноски). Абзац, разорванный страницей или колонкой, склеивается автоматически. Тексты на русском и английском; деление на предложения учитывает сокращения («т. е.», «et al.») и инициалы.
- На странице текста преподаватель проверяет разбивку: склеивает и разрезает фрагменты между предложениями, меняет их тип, задаёт норму чтения и режим показа. Для каждого абзаца видно, через сколько секунд откроется маркер задания.
- PDF без текстового слоя (сканы) отклоняется с понятным сообщением: распознавание пока не поддерживается.
- Преподаватель публикует текст; после публикации студенты видят его в курсе, а разбивку править нельзя.
- Читалка показывает страницы PDF. Абзац дочитан, когда пробыл в средних 60% экрана половину расчётного времени; при неактивной вкладке таймер стоит. Сервер засчитывает не больше времени, чем прошло по его часам. Преподаватель видит предпросмотр с зоной чтения и счётчиками и сводку: сколько абзацев дочитал каждый студент.
- Спрятанные задания: привязанные к абзацу (у всех в одном месте) или раскиданные по разделу либо диапазону страниц (у каждого студента в своём абзаце, место закрепляется при первом открытии). Маркер появляется на полях, когда абзац дочитан. Ответы: выбор варианта и выделение предложения проверяются автоматически, короткий ответ до трёх предложений засчитывает преподаватель. Ответы можно менять до дедлайна; результат студент видит после него.
- Чтение с телефона: веб-текст, свёрстанный из абзацев. Текст в режиме PDF на узком экране открывается текстом, есть переключатель «Текст / Страницы PDF».
- Результаты текста: кто что нашёл и ответил, баллы за задания (8 поровну между заданиями, засчитываются принятые ответы), карта дочитывания по абзацам, выгрузка в CSV для Excel. После дедлайна студент видит свои баллы в читалке.
- Тёмная тема по дизайн-системе: чёрный фон, Inter (из npm, без Google Fonts), фиолетовый только для главного действия экрана.

## Быстрая проба на своём компьютере

1. Установите и запустите [Docker Desktop](https://www.docker.com/products/docker-desktop/).
2. На GitHub выберите ветку `claude/upbeat-planck-ujhlu0`, нажмите **Code → Download ZIP** и распакуйте архив.
3. Запустите из распакованной папки:
   - Windows: двойной щелчок по `start-local.bat`;
   - macOS и Linux: в терминале `sh start-local.sh`.

   Первый запуск занимает 5–10 минут.
4. Откройте http://localhost:3000. Войдите как `teacher@test.ru` — это преподаватель, любая другая почта — студент. Письма не нужны: ссылка для входа появится прямо на странице.

Остановить: `docker compose down` в той же папке (данные сохранятся). Тестовый режим (`DEV_LOGIN_LINKS=true`) пускает кого угодно под любой почтой, поэтому он только для своего компьютера.

## Структура

```
web/                 приложение на Next.js (App Router, TypeScript)
  prisma/            схема базы и миграции (PostgreSQL)
  src/lib/           доступ к данным: вход, сессии, курсы
  src/app/           страницы и server actions
  tests/             тесты Vitest (часть идёт на настоящей базе)
pdf-service/         разбор PDF на абзацы и предложения (Python, FastAPI, PyMuPDF)
  app/extract.py     правила деления на абзацы
  tests/             тесты pytest на сгенерированных PDF
docker-compose.yml   база, сервис разбора, миграции и приложение одной командой
```

## Локальный запуск

Нужны Node.js 22, Python 3.13 и PostgreSQL 16.

Сервис разбора PDF:

```bash
cd pdf-service
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -q                                  # тесты
.venv/bin/uvicorn app.main:app --port 8000           # http://localhost:8000
```

Приложение:

```bash
cd web
cp .env.example .env        # проверьте DATABASE_URL и TEACHER_EMAILS
npm install
npm run db:migrate          # создать таблицы
npm run dev                 # http://localhost:3000
```

Пока не задан `SMTP_URL`, ссылка для входа выводится в лог сервера. Дедлайны вводятся и показываются в поясе `APP_TIMEZONE` (по умолчанию `Europe/Moscow`). Загруженные PDF складываются в каталог `STORAGE_DIR` (по умолчанию `web/storage`).

Проверки перед коммитом:

```bash
npm run lint && npm run typecheck && npm test && npm run build
```

Тесты очищают таблицы, поэтому работают на отдельной базе `TEST_DATABASE_URL` (имя должно кончаться на `_test`, иначе тесты откажутся запускаться) и сами накатывают на неё миграции. Сервис разбора в тестах веб-части подменяется, запускать его не нужно.

## Запуск на сервере

Пошагово, вместе со сценарием пробного прогона с коллегами: [docs/deploy.md](docs/deploy.md).

Коротко: `cp deploy/.env.example .env`, заполнить домен, почту и пароль базы, затем `docker compose up -d --build`. Стек — база, сервис разбора PDF, приложение и Caddy, который сам получает HTTPS-сертификат.
