# Как запустить «Поля» и проверить с коллегами

Инструкция для первого запуска на сервере и пробного прогона с 3–6 коллегами. Нужны базовые навыки работы в терминале: подключиться к серверу по SSH и выполнить команды.

> Хотите просто попробовать систему у себя? Хватит раздела «Быстрая проба» в [README](../README.md): Docker Desktop и один файл запуска.

## Что понадобится

| Что | Зачем | Где взять |
| --- | --- | --- |
| Сервер с Ubuntu 24.04: 2 ядра, 4 ГБ памяти, 30 ГБ диска | На нём работает всё: сайт, база, разбор PDF | Yandex Cloud, Selectel, Timeweb Cloud. Для данных студентов лучше российский хостинг |
| Домен или поддомен | Сайт работает только по HTTPS, сертификату нужен домен | Свой домен (`polya.example.ru`). Если домена нет, подойдёт бесплатный `<IP-сервера>.sslip.io` |
| Почтовый ящик для отправки писем | Вход по ссылке из письма | Яндекс Почта с паролем приложения (шаг 4). Можно обойтись без почты, см. шаг 8 |
| Доступ к репозиторию `stainephone-gif/hsereading` | Чтобы скачать код на сервер | GitHub |

## Шаг 1. Создать сервер

1. Создайте виртуальную машину с Ubuntu 24.04 и публичным IP-адресом.
2. Откройте входящие порты 22 (SSH), 80 и 443 (сайт). В Yandex Cloud это группа безопасности, у других провайдеров — «файрвол».
3. Подключитесь: `ssh <пользователь>@<IP-адрес>`.

## Шаг 2. Домен

- **Свой домен.** В DNS добавьте A-запись: `polya.example.ru → <IP-адрес сервера>`. Подождите, пока она заработает: `ping polya.example.ru` должен показать нужный IP.
- **Без домена.** Ничего настраивать не нужно: имя `203.0.113.10.sslip.io` (с вашим IP) само указывает на сервер.

## Шаг 3. Установить Docker и скачать код

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # затем выйдите и зайдите по SSH заново

git clone https://github.com/stainephone-gif/hsereading.git polya
cd polya
git checkout claude/upbeat-planck-ujhlu0   # после слияния в main этот шаг не нужен
```

Репозиторий закрытый, поэтому `git clone` спросит логин и пароль GitHub. Вместо пароля введите токен: GitHub → Settings → Developer settings → Personal access tokens, право `Contents: Read` на этот репозиторий.

## Шаг 4. Почта для ссылок входа (Яндекс)

1. Зайдите в ящик, с которого будут уходить письма, например отдельный `polya.pilot@yandex.ru`.
2. Яндекс ID → Безопасность → Пароли приложений → создать пароль для почты.
3. Запомните логин и пароль приложения, они нужны на следующем шаге.

## Шаг 5. Настройки

```bash
cp deploy/.env.example .env
openssl rand -hex 24          # случайная строка для пароля базы
nano .env
```

Заполните:

```ini
DOMAIN=polya.example.ru                 # или 203.0.113.10.sslip.io
APP_URL=https://polya.example.ru        # https:// + DOMAIN, без слеша в конце
POSTGRES_PASSWORD=<строка из openssl rand>
TEACHER_EMAILS=you@hse.ru               # кто может создавать курсы, через запятую
SMTP_URL=smtps://polya.pilot%40yandex.ru:<пароль-приложения>@smtp.yandex.ru:465
MAIL_FROM=Поля <polya.pilot@yandex.ru>
APP_TIMEZONE=Europe/Moscow
```

`@` в логине внутри `SMTP_URL` записывается как `%40`. Если в пароле приложения есть `@`, `:` или `/`, их тоже нужно закодировать.

## Шаг 6. Запуск

```bash
docker compose up -d --build
```

Первая сборка занимает 5–10 минут. Затем проверьте:

```bash
docker compose ps
```

Должно получиться так: `db`, `pdf`, `web`, `caddy` в состоянии `running`, а `migrate` — `exited (0)`. Миграции базы выполнены, и этот контейнер завершился, так и должно быть.

Откройте `https://<ваш домен>`: должна появиться страница входа. Если браузер ругается на сертификат, подождите минуту: Caddy получает его при первом обращении.

## Шаг 7. Проверка самому, до коллег

1. Войдите с почты из `TEACHER_EMAILS`: введите адрес и откройте ссылку из письма.
2. Создайте курс и откройте его.
3. «+ Загрузить PDF»: возьмите статью, которую дадите коллегам.
4. Проверьте разбивку на абзацы. Абзац, разорванный страницей, склейте. Два абзаца в одном фрагменте разрежьте кнопкой ✂.
5. Добавьте 3–4 задания разных видов:
   - выбор варианта в конкретном абзаце;
   - выделение предложения в конкретном абзаце;
   - короткий ответ в конкретном абзаце;
   - короткий ответ, раскиданный по разделу («Перескажите этот абзац одним предложением»).
6. Поставьте дедлайн через пару дней.
7. «Предпросмотр читалки»: прокрутите текст и убедитесь, что абзацы дочитываются, а маркеры появляются.
8. Нажмите «Опубликовать».

Для теста из второго окна можно войти студентом с другой почтой в режиме инкогнито.

## Шаг 8. Пробный прогон с коллегами

**Что разослать.** Ссылку-приглашение со страницы курса (`https://…/invite/…`) и короткое письмо:

> Откройте ссылку, введите свою почту и войдите по ссылке из письма. Читайте текст как обычно: по ходу чтения на полях появятся задания. Ответьте на те, что найдёте. Попробуйте открыть текст и с телефона.

Хорошо, если хотя бы один коллега будет с iPhone и один с Android.

**Если почта не настроена.** Ссылки для входа пишутся в журнал сервера. Когда коллега запросит вход, найдите его ссылку и отправьте ему в мессенджер:

```bash
./deploy/login-link.sh colleague@hse.ru
```

Ссылка действует 15 минут. На один адрес можно запросить не больше 5 ссылок за 15 минут.

**Что делаете вы во время прогона:**

1. Страница текста → «Результаты»: видно, кто открыл текст, что нашёл и сколько абзацев дочитал.
2. Короткие ответы проверяются на странице текста, в разделе «Спрятанные задания»: «Зачёт» или «Незачёт».
3. Чтобы показать коллегам их баллы, передвиньте дедлайн в прошлое (Настройки → Дедлайн). В читалке появятся «Баллы за задания».
4. «Скачать CSV» — таблица для Excel.

**О чём спросить коллег:**

- Удалось ли войти? Сколько времени шло письмо?
- Заметили ли маркер задания? Сколько заданий нашли и где искали остальные?
- Удобно ли было читать с телефона: текст, переключатель «Текст / Страницы PDF», выбор предложения?
- Было ли ощущение, что за ними следят или торопят?
- Что непонятно в интерфейсе?

**Что посмотреть самому:**

- Карта дочитывания: какие абзацы пролистали все.
- Насколько точно разобрался PDF и сколько пришлось править руками.

## Обновление до новой версии

```bash
cd ~/polya
git pull
docker compose up -d --build
```

Данные (база, загруженные PDF, сертификат) хранятся в томах Docker и при обновлении сохраняются. Миграции базы выполняются сами.

## Резервная копия

```bash
# База
docker compose exec -T db pg_dump -U polya polya > backup-$(date +%F).sql
# Загруженные PDF
docker run --rm -v polya_files:/data -v "$PWD":/backup alpine tar czf /backup/files-$(date +%F).tar.gz -C /data .
```

Имя тома начинается с имени папки проекта (`polya_files`, если код в папке `polya`). Проверить его можно командой `docker volume ls`.

## Если что-то не так

| Признак | Что проверить |
| --- | --- |
| Сайт не открывается | `docker compose ps`: все ли контейнеры запущены. Открыты ли порты 80 и 443 у провайдера |
| Ошибка сертификата дольше пары минут | Указывает ли домен на IP сервера. `docker compose logs caddy` |
| Письмо со ссылкой не приходит | Папка «Спам». `docker compose logs web` покажет ошибку SMTP. Проверьте `SMTP_URL` и пароль приложения |
| После входа снова просит войти | `APP_URL` должен начинаться с `https://` и совпадать с адресом в браузере. По HTTP вход не работает |
| «Слишком много запросов» при входе | Больше 5 ссылок на один адрес за 15 минут. Подождите |
| «В PDF нет текстового слоя» | PDF — это сканы страниц картинками. Нужен PDF с текстом: его можно выделить мышкой в обычном просмотрщике |
| Создать курс может не тот | `TEACHER_EMAILS` в `.env`. После правки: `docker compose up -d` |

Журналы всех частей: `docker compose logs -f`. Остановить всё: `docker compose down` (данные сохранятся).

## Запуск на своём компьютере

Подходит для пробного прогона, если коллеги в той же сети, что и ваш компьютер: офис, общий Wi-Fi. Сервер и домен не нужны. Компьютер должен быть включён и не уходить в сон, пока идёт тест.

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows или macOS) и запустите его.
2. Скачайте код: `git clone https://github.com/stainephone-gif/hsereading.git polya`, затем `cd polya` и `git checkout claude/upbeat-planck-ujhlu0`.
3. Узнайте адрес компьютера в сети:
   - Windows: `ipconfig`, строка «IPv4-адрес», например `192.168.1.10`;
   - macOS: Системные настройки → Сеть → Wi-Fi → Подробнее, строка «IP-адрес».
4. Создайте файл `.env` в папке проекта:

   ```ini
   APP_URL=http://192.168.1.10:3000
   WEB_BIND=0.0.0.0
   POSTGRES_PASSWORD=любая-строка
   TEACHER_EMAILS=you@hse.ru
   SMTP_URL=
   APP_TIMEZONE=Europe/Moscow
   ```

   Вместо `192.168.1.10` подставьте свой адрес. `SMTP_URL` можно заполнить, как на шаге 4, тогда письма будут уходить по-настоящему.
5. Запустите без Caddy (он нужен только для HTTPS с доменом):

   ```bash
   docker compose up -d --build db pdf migrate web
   ```

6. Откройте `http://192.168.1.10:3000` у себя, затем с телефона в той же сети. Если не открывается, разрешите Docker входящие подключения в брандмауэре Windows или macOS.
7. Без почты ссылки для входа берите так: `./deploy/login-link.sh colleague@hse.ru`. В Windows, если скрипт не запускается, используйте `docker compose logs web` и найдите строку с `token=`.

Для теста с коллегами можно добавить в `.env` строку `DEV_LOGIN_LINKS=true`: ссылка для входа появится прямо на странице, письма не нужны. Но тогда любой в сети сможет войти под любой почтой, в том числе вашей. Годится только для коллег и только на время теста.

Ограничения такого запуска:

- **Без HTTPS.** Сайт работает по `http://`: годится для теста с коллегами, но не для настоящих студентов и их данных.
- **Только локальная сеть.** Из дома коллеги не подключатся. Для удалённого теста нужен сервер (шаги 1–6) или туннель с публичным HTTPS-адресом, например `cloudflared tunnel --url http://localhost:3000`. В этом случае `APP_URL` — выданный туннелем адрес `https://…`, а `WEB_BIND` можно не задавать. Туннель я не проверял.
- **Адрес может смениться.** Если IP компьютера в сети изменился, поправьте `APP_URL` и выполните `docker compose up -d web`.

Только для себя можно ещё проще: `APP_URL=http://localhost:3000` и тот же запуск.

## Известные ограничения пробной версии

- Пасхалок пока нет: максимум за текст 8 баллов, а не 10.
- Задание нельзя отредактировать: только удалить (вместе с ответами) и создать заново.
- Разбивку опубликованного текста править нельзя. Сначала снимите текст с публикации.
- Итоговой оценки по курсу («6 лучших из 8») ещё нет: баллы считаются по каждому тексту.
